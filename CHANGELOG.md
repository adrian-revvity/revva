## [1.2.0] - 2026-10-29

- **Pick the worktree and branch from the conversation** — Details now lists Revva's own worktrees (linked ones *and* the repository's main checkout) and the branches git reports for that repository, so a conversation can be moved to another checkout or switched to another branch without ever navigating a folder. Each list says what it means: which worktree is current, which one a ticket owns, which branch another worktree already holds (disabled, with the path), and which branches only exist on a remote — choosing one starts the local tracking branch. Moving a conversation moves its OpenCode session, so the agent works where you picked, and its review anchor is re-read from git; nothing is renamed, deleted or force-checked-out. Anything unsafe is refused before the first write with the reason and "Nothing was changed": a running response, a live review/ship/follow-up, a shipped run, a PR-linked conversation off its PR's branch, an agent or terminal inside either folder, a checkout with uncommitted changes, a branch two remotes both carry.

- **Repo workflow skills cannot hijack Revva sessions** — every Revva-created conversation (ticket build, ticket/PR chat, reviewers, fixer, conflict/rework sessions) is now created with service-enforced permission rules denying the skills the repository itself ships (e.g. a checked-in `.claude/skills/jiraWork`), while global/user skills keep working. The OpenCode service drops even a model-initiated activation of a denied skill, so a ticket prompt can no longer be swallowed by a repo skill that halts on a missing plugin. Deny lists are discovered per folder and cached; if the skill listing fails the session is created ungated rather than locked down. To use a repo skill with an agent, run it outside Revva (e.g. the OpenCode TUI) in that checkout.

- **Chat with this ticket** — every Jira card now carries a full-width **Chat with this ticket** button under Start, matching the PR cards. It opens the conversation immediately instead of quietly creating a session in the background. The old icon-only session button is gone.

- **Ticket and PR chats open empty** — “Chat with this ticket” and “Chat with this PR” no longer send a kickoff message the moment they open (no more wall of template text or “acknowledge this” above your first message). The ticket/PR brief is installed as a hidden per-session instruction the OpenCode service injects into every turn without adding anything to the transcript, so the conversation starts genuinely blank and the agent still knows exactly which ticket or PR it is on. Older services without the instruction endpoint fall back to appending the context underneath *your* first message only. The Setup-tunable tackle prompt remains the ticket chat's brief.

- **Workflow-skill guard for ticket conversations** — build *and* ticket-chat prompts now carry an always-appended guard: work from Revva's prompt directly, never run the repository's ticket/review workflow skills (e.g. `/jiraWork`, `/reviewPR`), and never stop because such a skill demands an unenabled plugin like `superpowers`. A missing skill or plugin only counts as a blocker when the implementation itself truly needs it. Previously only the pipeline build prompt got the note, so “Chat with this ticket” sessions still died at the repo skill's plugin gate.

- **Full-team rerun and clearer Workflow status** — Workflow now explicitly offers Re-run all reviews, starting a fresh reviewer round and the normal fixer/re-review flow when needed. The header uses blue for ready/active work, amber for fixing/attention and green only for approved/shipped work. Its popover is narrower, with agent/model details on a second line instead of stretching the review list across the screen.

- **Review can be restarted from Ready** — restored the always-visible Start/Re-run review action in Workflow, with explicit disabled reasons while implementation or review is running. Ready conversations can retry a reviewer or resume a stopped fixer, and PR menus expose the same review entry point. Active-session, queued-follow-up and checkout safety checks remain enforced before launching agents.

- **Visible conversation detail** — live text, reasoning and tool updates are delivered only to displayed transcripts, including open reviewer dialogs. Hidden/minimized windows suspend detail and resnapshot on return; switching conversations preserves authoritative history recovery and background runs, questions and completion notifications.
- **Less conversation fetch overhead** — incremental stream batches replace accumulated text snapshots, abandoned history requests are cancelled, work-state changes no longer refresh unrelated transcripts, context usage retains completed-step accounting instead of full-context heartbeat polling, Inbox recovery is bounded, and finished-card previews fetch compact latest answers. Opt-in `REVVA_DEBUG_PERF=1` diagnostics report content-free numeric aggregates; no unmeasured speedup is promised.
- **Conversation recovery edge cases** — rapid switching waits for the current transcript subscription, renderer reloads/crashes release old subscriptions and cancel abandoned HTTP requests, and reset/revert cannot restore stale context usage. Hidden/minimized windows also disable history/context queries and cancel abandoned history loads, rather than fetching transcripts on background completion. Model/agent picker inventory loads only when opened, with explicit cold-loading and failure states.
- **Mid-response catch-up without background broadcasting** — a bounded active-prefix cache retains observed text, reasoning and compact tool state so switching back or restoring a window can recover a draft that OpenCode has not persisted yet. Prefixes are limited by bytes/count, expire after completion and are invalidated on reconnect/revert. Ordinary stream batches and heartbeat responses do not resend full prefixes; missed/evicted prefixes wait for authoritative recovery rather than repeatedly refetching or showing a partial tail as the whole message.

- **Copy subagent session IDs** — every reviewer/fixer output header now shows its own session ID with a copy button, so the full ID can be pasted into another conversation. This uses the subagent’s session, not the ticket’s primary conversation.

- **Agent-driven worktree cleanup** — the worktree dialog's per-row “Can I remove this?” checks are replaced by one “Clean up with agent” button that opens a chat where an agent audits every worktree Revva can see (uncommitted, untracked, unpushed or unmerged work) and removes the provably-safe ones itself with plain `git worktree remove` — never `--force`, never `branch -D` — then reports what it kept and why. Worktrees tied to live revva work or locked by git are listed as off-limits. Manual selection with the safety-proof confirmation dialog is unchanged.

- **Toast for every PR action** — merge, rebase, stack rebase, push, AI description save and the review/conflict/comment session starters now report their result (success or the exact failure) as a toast, so outcomes are visible even after the card menu or dialog that triggered them has closed.

- **Proportional ticket investigation** — default build and ticket-chat prompts now guide agents to inspect the relevant code, batch independent discovery, reuse findings, and move to implementation once the change is understood, while retaining required verification and safety checks. Custom prompts remain unchanged. The repository agent guide now includes the same working rules and a compact file map to reduce repeated discovery.
- **GitHub sidebar alerts recover after recurring updates** — resolved conflicts, revoked approvals and resolved review threads now rearm the GitHub sidebar indicator for the next change. It updates on every successful Mine refresh and acknowledgment, with background checks every minute instead of five. Failed or incomplete GitHub lookups keep existing alerts, and temporary unknown mergeability no longer clears a conflict alert. Desktop-notification behavior and cadence are unchanged.
- **Review sessions survive a Revva restart** — reviewers and fixers reconnect to their existing OpenCode executions instead of being falsely marked failed. Live events and completed executions missed during a disconnect are reconciled before retrying, without starting duplicate agents; explicit Stop review remains stopped.
- **Resume a stopped fixer, and recovery actions in every agent dialog** — Resume fixer keeps the original session and any partial, uncommitted fixes instead of rejecting them as a changed worktree. Each reviewer/fixer dialog now exposes retry/relaunch or resume, plus Stop review while running, with clear explanations for disabled actions. Read-only reviewer retries still require the same reviewed commit; no files, branches or partial work are reset.

- **One close control in agent dialogs** — removed the redundant “close” text button from reviewer/fixer output dialogs; the dialog’s own close button and Escape still dismiss them.
- **Subtle agent status colors** — reviewer and fixer cards use faint status-tinted backgrounds and borders, with blue for active work, green for approval, amber for changes or waiting on you, and red for errors. Queued and skipped agents stay neutral; labels and icons remain, with theme-aware colors for light and dark mode.
- **Follow-ups during review and fixing** — messages are saved in a ticket-level queue instead of failing after Send. Edit or remove queued messages, or stop review and send immediately; pending instructions run before shipping and their changes go through review again. Four visible agent cards show live reviewer/fixer activity and open each agent’s output in a dialog, including requests waiting on you.
- **Active work in the Inbox meter** — the Inbox’s active meter now includes ticket work in the same active states as the sidebar, even when its background agent sessions are not the ticket’s primary session.
- **Ticket status stays visible beside its chat** — sidebar chat entries now show their linked ticket workflow state, and the Workflow popover displays agent/review details inline instead of opening a separate dialog.
- **Ticket-linked chats stay ordinary chats** — existing conversations still get ticket workflow controls, but no longer receive build-completion instructions or trigger automatic review/fixer rounds just because they are linked to a ticket.
- **PR chats ignore stale review gates** — ordinary PR-linked conversations no longer inherit build-completion instructions or auto-review behavior from a leftover review-after-follow-up flag.
- **Chat with a PR uses your general chat setup** — it now reuses the agent and model from the last New chat selection instead of the dedicated PR-review role; PR linking, workflow actions and headers are unchanged.

## [1.1.0] - 2026-10-29

Revva 1.1 — one conversation chrome for Jira, PRs and tagging; reviews that wait for a real *done*; and honest speed. PR review threads can be answered from the card, queued follow-ups can steer the running turn, the sprint board grew issue types, sub-task launching and family linking, worktree removal grew an audit chat, and conversations got quieter, faster and more precise (since-Send tok/s, effort picker, quiet-since timer).

- **Quieter conversation header** — Jira and PR conversations now use one compact Workflow control for status, review and delivery actions. Agents and their transcripts open in a floating review window; folder, branch, model and session details move into Details. The title appears once; permanent idle-agent and review-folder bars, duplicate status badges and repeated model/session pills are gone, without changing the underlying flows.

- **Lighter live conversations** — session metrics share one IPC batch per second and update only the stats card; their single clock stops when no runs remain. Transcript recovery polls every 10 seconds instead of 3, fetches newest pages with overlap, and preserves cached history; reconnects and edits still reload an authoritative snapshot. Tool refresh bursts and streamed text each use one shared coalescer, with indexed live-message updates and linear snapshot pruning. Images are lazy-loaded through a bounded 32 MiB attachment cache instead of repeatedly copying base64 over transcript IPC. Stats have no tooltips and show tool/other phase totals inline. Removed the unused, unwired stale-session watchdog.

- **One conversation UI for Jira, PRs and tagging** — starting a Jira ticket, opening a GitHub PR conversation, or linking an existing chat all show the same agent/review/fixer/shipping utilities. Jira/PR links are conversation properties that control sidebar grouping and enable those flows; tagging preserves the session, transcript and review history rather than starting another run. The team bar appears before agents start, but reviewers still wait for completed implementation. No checkout, agent prompt or session restart happens just from adding a link, and removing the last link keeps the conversation and files.

- **Abandon no longer claims a missing branch was kept** — cleanup checks the exact branch ref after a deletion refusal. Legacy detached worktrees whose recorded branch never existed now abandon without a misleading warning; real retained branches and unverifiable cleanup still report a note.

- **Review waits for completed implementation** — a build agent must explicitly end its reply with `REVVA: DONE` after implementing, verifying and committing. A planning pause or missing-plugin error now lands in Needs you instead of immediately spawning code/test/UI reviewers and a fixer. Manual Re-run review remains available.
- **Stop a broken review before abandoning** — the review panel now has Stop review, which interrupts this ticket’s reviewers and fixer, including sessions left running in OpenCode after Revva restarted. It confirms they are inactive and keeps files/transcripts; Abandon still refuses to delete an occupied worktree. Follow-ups and review retries also check for orphaned active review sessions.
- **Ticket worktrees get an explicit branch and base** — service-created worktrees now request the Revva ticket branch from the default branch (or chosen parent), record the base and verify the checkout instead of accepting a detached HEAD on the main checkout’s current feature branch.

- **"Can I remove this?" check on every worktree row** — each row in the worktree cleanup dialog opens an audit chat that reads the worktree (uncommitted, untracked, unpushed or unmerged work) and answers in plain terms whether removal is safe or what must be committed/saved first. The check never changes anything — deleting still goes through the confirmation dialog.
- **Worktree cleanup no longer lists ghosts** — the OpenCode service keeps a registry row for every worktree it ever created, and rows for folders deleted outside OpenCode (`git worktree remove`, `rm -rf`) lingered forever, inflating the cleanup dialog with dozens of dead entries. Entries whose folder no longer exists are now dropped from the listing; git's own listing (which covers every real registration, prunable ones included) remains the source of truth.
- **Worktrees whose folder is already gone can be cleaned up again** — removing one failed with "active agents cannot be ruled out — the OpenCode service could not be consulted (Location not found…)" because the OpenCode service refuses to report terminals for a directory that no longer exists, and that refusal was treated as an occupancy check that failed. A gone folder provably hosts no terminal, so its stale registration is now cleared as before; any other service failure, and a service that claims to not know a folder that still exists, still block removal.
- **Ticket type on Jira cards, sub-tasks with Start** — every board card now carries an issue-type badge (Story, Bug, Sub-task, Epic…), coloured per type. Cards show a checklist badge that opens the ticket with its sub-task list — type, status, summary — and a **Start** button on each one, which opens the same Start flow scoped to that sub-task (done sub-tasks are struck through and not startable; a live work on a sub-task shows its state instead and jumps to it).
- **Jira cards look like PR cards** — the sprint board's ticket cards were rebuilt on the GitHub card's layout: summary as the title (click opens the sub-task dialog), a muted mono line under it with the key and points, status/type/sub-task badges on their own wrapping row, and a bordered footer with a full-width **Start** button (solid when a work is live on the ticket, then it jumps to it) above the quiet pin / park / chat icons and an *Open on Jira* button at the far right.
- **Parent ↔ sub-task relationships visible on the board** — a sub-task card carries a violet `↳ on PROJ-123` badge (like a stacked PR's `on <branch>` badge): hovering any card lights up its whole family with the same violet ring, and clicking the badge scrolls to and pulses the parent card (un-parking it from "Not right now" if needed). A parent's card is highlighted by the same hover chain. The sub-task dialog is sized for the job — wide, one line per sub-task, open work listed before done, header pinned while only the list scrolls — and every open refetches from Jira instead of trusting a cached answer.
- **Steer a queued message now** — each queued follow-up in the strip above the composer has a **Steer now** button: the message stops waiting for the queue and is injected into the running turn at its next step boundary instead. Injected messages read **Steering into this turn** until the agent picks them up. Works in chats and ticket cockpits.
- **Answer the review comments** — PR cards with unresolved review threads show an **N unresolved** button: Revva opens a chat checked out on the PR's branch (the ticket's own worktree when it exists) primed to verify each thread against the code, fix valid feedback, push to the PR head, reply under each thread and resolve it. New review threads since you last looked now also raise the bell and the unseen-updates strip, like comments always did.
- **Live model speed, honest average** — the speed card now reads output tokens per wall-clock second **since Send**, so initial wait, network delays, retries and tool time all count against the rate instead of a flattering last-10-seconds burst. It freezes when the run ends and survives switching chats; completed steps reconcile with the provider's real token counts. Card styling is more compact and muted.
- **See how long a chat has been quiet** — the chat stats card shows seconds without streamed text, reasoning, or tool input and **stops when the answer lands**. Tool execution and other elapsed phase totals are visible inline, without hover UI; other time includes streaming and local preparation, not just provider latency.
- **Choose reasoning effort in the composer** — when the selected model exposes effort variants, set its effort for subsequent turns without switching models. Removed the redundant Enter-to-send hint; Enter sends and Shift+Enter adds a line.
- **See the current agent step while it thinks** — the conversation footer keeps a small **Thinking** badge visible and shows the current step plus the latest tool and its short detail, even while the transcript’s tool list is collapsed.
- **Fixed duplicate transcript rows** — a snapshot refetched right after a turn could re-render assistant steps that were already on screen; history and live text now merge strictly by message id.
- **Issue types & sub-tasks on ticket cards** — Jira cards carry an issue-type badge (Story, Bug, Sub-task…, with a stable color per type), and a card with sub-tasks opens a dialog listing them with their live pipeline state — start work on a sub-task directly from there.
- **Quieter logs: no deprecation noise, no false worktree errors** — the Jira token store moved to Electron's async `safeStorage` API (the sync calls Electron 45 deprecates and 46 removes; existing tokens decrypt unchanged). The worktree cleanup listing no longer runs git on workspace folders that are plain containers or on deleted repos, which logged `list failed … not a git repository` on every refresh.
- **Stats card shows Idle only** — the Tools and Other phase timers left the chat stats card; the single **Idle** row is the number people actually watch. Context, Speed and Idle remain.
- **No fake "Thinking…" bubble after Send** — the transcript used to render a placeholder assistant card (ours, never the model's) until the first token arrived, duplicating the **Thinking** badge in the footer. The transcript now stays quiet until the turn has real content — reasoning, tool steps or text.

## [1.0.0] - 2026-10-29

Revva 1.0 — the "run it all day" release. The GitHub and Jira boards are now drag-and-drop tile views with a PR menu that carries review, conflicts, push, rebase, merge and AI-written descriptions; conversations switch model and agent mid-run, group tool steps, show live context and tokens/sec, and never lose output when you switch away; the triage inbox became a single clear-the-queue view with OS notifications and a thinking meter; keep-awake holds off Mac sleep during long runs; and worktree removal now proves what it destroys before deleting anything.

- **Safer worktree removal** — abandoning a ticket or removing worktrees now previews exactly what deletion destroys (uncommitted, staged, untracked and ignored files are counted, never shown) and needs your explicit tick per worktree whenever files would go; the main checkout, unregistered folders, nested or locked worktrees are off-limits, active agents (or their absence being unprovable) block removal, and the confirmation is bound to a fingerprint of the actual contents — staged contents (full blob hashes), sizes, times, inodes, nested ignored content included: content staged, added, removed, or normally edited between preview and deletion aborts with nothing touched, and trees too large to fully verify are refused. `git worktree remove --force` is used only for content you confirmed destroying; branches still go through `branch -d` only. Abandoning while a review round is in flight now refuses instead of cancelling it — if a removal is refused or fails, nothing (not even review rounds) was changed. Removal is not race-free (a same-size rewrite that restores exact timestamps slips past the fingerprint, and writes after the last check cannot be caught) — the dialog says so.
- **Live model speed** — chat transcripts have a compact top-right card for context usage and estimated streamed tokens per second; the last measured speed remains visible when a response finishes. The rolling 10-second wall-clock window counts pauses with no output against the rate.
- **Update PR descriptions from the conversation** — the PR menu now sends a request to the current chat/work agent to inspect the latest commits and diff, update the PR description with `gh`, preserve text outside Revva's markers, and report back in the transcript. No separate draft-generation service or dialog.

- **Sidebar footer** — dropped the Reconnect button; the connection status opens Setup, which already has Retry, and Revva re-probes the OpenCode service on its own.
- **Switch model & agent mid-conversation** — the composer footer now carries a model and an agent button: pick another one and the next turn runs with it, same conversation and history intact (works in chats and ticket cockpits, and follows switches made from the TUI or other clients). In the model list, the models starred in Setup sit in a **Favorites** section on top; gated models stay disabled, and a chat's new pick carries over to its `/new` sessions and sidebar info.

- **Chat with this PR opens instantly** — the button no longer clones the repo into a review root. It is a conversation, not a checkout: the chat opens in one of your own folders when Revva recognizes one (a live worktree on the PR's branch, a live worktree of the PR's ticket, a registered workspace of that repo), otherwise in the same default as the New chat dialog (last selection, then last chat). The primer tells the agent when the directory isn't the PR's checkout, so it reads the PR through `gh` instead of local files. (The review, conflict and rebase flows still clone when they truly need the code, and their clone command was fixed — `--quiet` is now passed to git after `--`, which `gh repo clone` requires.)

- **Clear idle chats in one sweep** — a quiet button at the end of the sidebar’s Chats list deletes every unticketed chat that is at rest — not thinking, not waiting on you, not unread, not the one open (the OpenCode sessions go too). The confirm dialog lists what’s about to go.

- **Shipped works can be removed** — the Abandon button now appears on *Shipped work* rows too, so a finished ticket's work can be cleared from the sidebar; it removes the worktree and build session and deletes the branch only if it is fully merged.
- **Keep-awake toggle** — a coffee-cup button in the sidebar footer (next to the connection status) acts like *caffeinate*: while on, Revva holds off the Mac's sleep and display dimming so long agent runs aren't interrupted by a closed-lid nap. The choice is remembered across restarts.
- **Manage chats from ticket groups** — hovering a chat inside a ticket group now offers *Remove from ticket* (the chat drops back to the plain Chats list, transcript untouched) next to the existing trash button, so conversations can be detached or deleted without opening them first.
- **Instant New chat dialog** — the project, agent and model pickers load in the background as soon as Revva connects, so opening a new chat shows your last settings right away instead of "Loading chat settings…" for a few seconds.
- **Drag-and-drop ticket & PR cards** — Jira and GitHub cards are now compact tiles (minimum three across) that you can drag: drop one on the **Important** section to pin it up top, or into the collapsible **Not right now** shelf at the bottom to get it out of the way (it stays a drop target even while collapsed). Every card also has quiet pin / park buttons in its footer, and orders persist per view.
- **Inbox notifications** — finished chats and ticket work updates now raise a macOS notification, like questions and permissions always did; near-simultaneous events for one session collapse into a single alert.
- **Inbox thinking meter** — a card pinned to the Inbox’s top-right counts the sessions working right now; hover (or keyboard-focus) it to reveal each ticket and chat with its phase, and click one to jump straight there.
- **Tool steps collapsed by default** — the “Worked through N steps” list in an agent turn now starts collapsed; open it to inspect the steps.
- **Chat Markdown** — render formatted assistant messages while they stream, not only after completion.
- **Ticket conversation groups** — ticket work and linked chats appear together in expandable sidebar groups; GitHub review and conflict chats link to a clearly identified ticket (the PR title's CLN number wins when it differs from the branch), and chats can be moved between ticket groups or linked to a manually typed ticket number.
- **Chat with this PR** — every GitHub card has a big button that opens a brand-new chat linked to the PR and its ticket, opened in a fitting project folder without touching your checkouts. The agent gets a one-line PR primer and waits for you. Clicking the card's **title** opens a PR info dialog instead of GitHub: live state, branches, description, chats on this PR, and the same chat/review launchers; the GitHub button is now a small icon.
- **Unresolved review threads surface** — cards show a `⚠ N unresolved` badge (amber when new since your last look) for PRs with open GitHub review threads; new threads feed the bell and the unseen strip. Clicking the badge starts a chat on the PR's branch (your ticket worktree when it exists) primed to read every unresolved thread, fix valid feedback, push, reply inline to each thread and resolve it.
- **PR alerts are mine-only and findable** — the bell, the native notifications, and the new amber "unseen updates" strip on the GitHub page track only PRs you authored; review-requested PRs never alert. The strip lists each new comment/conflict/approval and clicking a row scrolls to and pulses its card. Nothing on the "Needs review" tab is fetched until you open that tab once, and the alert feed no longer refetches on window focus (main pushes every 5 min).
- **Stacked PRs read as stacks** — a PR whose base is another branch (not the repo's default) carries an `on <base-branch>` badge, and hovering any layer softly highlights every card of that stack across the board.
- **PR actions in conversations** — chats that link a PR (review, conflict-resolution, or any chat attached to one) and ticket cockpits with a PR now carry a PR menu in the header: start review, solve conflicts, push this conversation’s commits to the PR head (never force), rebase, merge (same rules as the GitHub cards), and open the PR on GitHub. When the PR's branch is part of a `gh stack` stack in a local checkout, the menu also offers **Rebase stack**, running `gh stack rebase` there and restoring the stack untouched on conflicts. PR-linked chats use the work hammer icon in the sidebar.
- **Pull request cards as tiles** — PRs sit in a responsive grid of compact square-ish cards: the title claims two lines, tags get their own full-width band so many badges never collide, and actions form a quieter footer row, so more PRs, tags, and actions fit on screen.
- **Conversation activity** — inbox chat cards show whether a session is thinking, ready, or waiting on you; active conversations also show a thinking indicator above the composer.
- **New chats** — reuse the last project, agent and model, with quick popovers to change them.
- **Conversation switching** — keep live messages while viewing another conversation, restore running state on return, and reconcile streamed text with history without losing earlier assistant steps or duplicating responses.
- **AI PR descriptions** — the PR menu’s **Update PR description with AI** asks the current conversation agent to read the PR diff and commits, update the description with `gh`, and report back in the transcript. New PRs still start from the ticket summary and commit list.
- **One PR menu** — the cockpit’s separate “PR actions” button is gone: push (through the ship checks), re-run review, the AI description and every GitHub PR action now live together in the single `PR #n` dropdown, in ticket cockpits and PR-linked chats alike.
- **Conversation composer** — preview Markdown, including inline and fenced code, and edit drafts without the cursor jumping to the end. Sent messages now display Markdown formatting.
- **Pull requests tab redesigned around action** — roomier cards; the solid button is whatever unblocks the PR (Solve conflicts, Rebase, or Merge), no merge button appears when merging is impossible, every card carries an Open PR button, merged PRs are gone from the list and badges, and unseen updates show a `new` tag with labeled Mark read / Mark all read instead of a permanent icon.
- **Reviewer questions** — review and fixer questions and permissions appear in the inbox without consuming the review timeout; reviewers use a pinned branch base and the changed UI paths.
- **Connection status** — inspect OpenCode and Jira connection health and reconnect Jira from the sidebar.
- **Inbox messages** — reliably load the latest assistant text from the conversation, with a retry if it can’t be fetched.
- **GitHub conflict resolution** — start a dedicated chat from a conflicted PR, using a fresh isolated worktree and a prompt to resolve conflicts without pushing automatically.

- **GitHub watch** — PR cards now flag merge conflicts, and new comments, conflicts or approvals raise a bell badge in the sidebar and an OS notification; both PR lists refresh in the background.
- **Merge and Rebase from Revva** — each open PR row offers Merge (squash / merge commit / rebase-merge, GitHub still enforces its rules) and Rebase, which replays the PR head onto its base in a throwaway worktree and pushes with force-with-lease; merging a linked ticket's PR marks the ticket shipped.
- **Inbox messages** — display the complete, formatted final response with an expandable view and more room to read.
- **Worktree count** — the sidebar shows linked worktrees in known repos and warns when there are more than 10 to review.
- **Inbox diagnostics** — show technical details when finished runs or pending questions fail to load, and indicate when retrying.
- **Review and shipping recovery** — explain how to investigate timed-out reviewers, accurately identify commits that passed review, and show why shipping is blocked or checks failed.
- **Inbox replies** — align the reply composer with chat, make Send the primary action, and move the conversation shortcut beside the title.
- **Review recovery** — inspect reviewer errors and retry individual reviewers or a failed fixer; ticket states use clearer labels.
- **Push / Open PR from the ticket conversation** — the cockpit header now always shows the ship action: **Open PR** once shipped, **Push / PR** whenever the run is at rest, and a disabled button explaining why while a session is running. Shipping outside green gates is allowed but warns in the dialog and is recorded on the ticket; AUTO keeps the hard reviewed-commit gate.
- **Sidebar sections** — ongoing ticket runs have their own section above chats, and the new-chat button sits under the Chats heading.
- **Inbox triage** — see each item’s type and position, browse without answering, and reply to finished chats directly from the inbox.
- **Triage inbox** — finished chats and ticket runs you haven’t opened now appear in the Inbox beside pending questions, ranked below them. One card at a time: answer or open it and the next slides in, like clearing an email queue. Mark read dismisses a card without opening; opening the chat or cockpit clears it everywhere.
- **Ticket conversations** — reduce duplicate header information, use shorter model labels, and move branch, worktree, model and session details into a top-bar popover.
- **Questions in conversations** — answer pending questions and permission requests directly in their chat or ticket transcript, as well as in the inbox.
- **Question inbox** — pending questions remain visible if the finished-run feed can’t load; the inbox now explains when Revva needs a restart or a retry.
- **Ticket review and shipping** — follow-ups and retries start fresh review rounds, review blockers are visible, and AUTO ships after required gates pass.
- **Conversation composer** — streamlined message entry, controls, and image previews into one compact layout.
- **Session IDs** — copy a conversation's session ID from its header to reference it in another chat.
- **Conversation context** — show context usage as a compact percentage beside the composer, with the token count in a tooltip.
